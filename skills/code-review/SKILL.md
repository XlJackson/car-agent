# 项目代码审查

按用户指定范围审查；只读请求只分析并报告，明确要求修复时再修改。

审查 Agent 调用链时，沿实际调用点检查消息回填、tool_use_id 对应、权限入口、Hooks 返回值和父子上下文边界。审查 README 时，将文档声明与相关实现核对，不把文档当成实现证据。

每项发现说明触发条件、实际行为、影响，并给出文件路径和函数；引用行号前先确认行号。优先报告可复现缺陷，避免将个人风格偏好或有意设计当作错误。

明确区分：源码确认的事实、测试验证的结论、仍需验证的推测。只抽查部分文件时写明范围，不能声称所有文件都符合某种模式。没有运行测试时不要说测试通过。

最终给出实质结论与依据；有问题时按影响排序，没有明确缺陷时如实说明，并列出未覆盖范围。收到子 Agent 摘要不等于主 Agent 已独立验证；报告实际核对过的内容。
